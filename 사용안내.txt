Codex 잔여 한도 오버레이 · 최소 기능 프로토타입

실행
0.5.0부터 ZIP을 풀어 사용하는 휴대용 형식입니다.
현재 소스 버전은 0.6.3이며 기본 표시 위치는 실제 세션 제목 아래입니다.
codex-usage-overlay-windows-x64.zip을 원하는 폴더에 압축 해제하고,
압축 해제한 폴더 안의 UsageOverlay.exe를 두 번 눌러 실행합니다.
Setup.exe나 install.ps1 실행, 고정 경로 설치, 관리자 권한이 필요하지 않습니다.
EXE만 따로 옮기거나 ZIP 안에서 바로 실행하지 말고 전체 폴더를 유지하세요.
일반 실행은 인수 없이 엽니다. --background 옵션은 제거했으므로,
이 옵션이 붙은 옛 바로가기는 새 버전에서 사용할 수 없습니다.
같은 파일을 다시 열면 이미 실행 중인 프로그램의 설정 창이 열립니다.
worker.mjs, probe.mjs, usage-state.mjs, runtime-paths.json을 EXE와 같은 폴더에 유지하세요.
Windows 10/11 x64, .NET Framework 4.8과 기존 Node/Codex 환경이 필요합니다.
Codex는 ChatGPT 계정으로 인증되어 있어야 합니다.
runtime-paths.json에 Node/Codex 실행 파일의 절대 경로나 EXE 폴더 기준 상대 경로를
지정할 수 있으며, 없는 실행 파일만 PATH의 node.exe/codex.exe로 대체합니다.
.cmd/.ps1 래퍼는 사용하지 않습니다. 경로나 환경을 수정하면 X 종료 후 다시 실행하세요.
Node/Codex 자체는 ZIP에 포함되지 않으며 자동으로 내려받거나 설치하지 않습니다.
다른 PC에서는 그 PC의 Node/Codex 설치, 계정 인증과 경로 설정이 필요합니다.

실행 방식
트레이 없는 일반 창 프로그램이며, 메인 설정 창이 작업 표시줄에 표시됩니다.
메인 창을 최소화해도 ChatGPT가 활성 상태이면 오버레이와 정기 조회를 계속합니다.
창 안에는 '종료' 버튼 하나를 두며, 이 버튼과 제목 표시줄의 X는
오버레이와 소유 조회 프로세스까지 정리하고 완전히 종료합니다.
Overlay의 Windows 로그인 자동 시작은 사용하지 않습니다.
사용자가 이미 설정한 ChatGPT의 Windows 로그인 자동 시작은 그대로 사용합니다.
함께 시작할 구체적인 방법은 아직 선택 중입니다.
제안한 수동 전용 바로가기는 별도의 'ChatGPT + 오버레이' 실행 아이콘입니다.
그 아이콘을 누르면 ChatGPT를 열거나 활성화하면서 Overlay도 시작하는 방식입니다.
원래 ChatGPT 아이콘이나 로그인 자동 시작 경로를 바꾸는 제안은 아닙니다.
동반 실행 런처는 아직 구현하지 않았고 바로가기도 생성하지 않았습니다.
Overlay용 Run 키, Startup 폴더, 예약 작업, 프로세스 감시는 등록하지 않습니다.
ChatGPT 창이 닫히거나 비활성화되면 오버레이 표시와 정기 한도 조회를 멈춥니다.
메인 창은 작업 표시줄에서 복원할 수 있습니다.

설치, 실제 실행, 바로가기 생성은 사용자가 해당 작업을 명시적으로 허용한 뒤 진행합니다.

표시 위치
표시 위치 드롭다운에서 '사이드바' 또는 '세션 제목 아래'를 선택합니다.
현재 선택한 위치의 이름을 표시하며 기존 위치 선택과 제목 아래 보정 값은 유지합니다.
사이드바는 아래의 하단 여백 방식으로 이관합니다.
Windows UI Automation으로 현재 창의 실제 제목과 헤더 영역을 읽어 위치를 정합니다.
가로 위치는 제목 왼쪽 + 가로 보정이며, 세로 위치는 제목/헤더 중 더 아래쪽 끝 + 아래 간격입니다.
기본값은 가로 보정 0, 아래 간격 6 DIP이며 화면 배율을 적용합니다.
가로 배치는 읽어낸 헤더의 콘텐츠 범위 안으로 제한합니다.
기본값인 '세션 제목 아래'를 사용하거나 설정 창에서 '사이드바'를 선택하세요.
'앱에서 확인'을 누르면 메인 창을 작업 표시줄로 최소화하고 ChatGPT로 돌아갑니다.
제목 아래에서는 제목 기준 가로 보정과 아래 간격을 조정할 수 있습니다.
사이드바의 가로 값은 창 왼쪽 기준이며 세로는 창 아래에서 배지 아래쪽 끝까지의 하단 여백입니다.
표시 항목에 따라 배지 높이가 자동으로 바뀌어도 하단 여백은 유지됩니다. 기존 SidebarY는 옛 배지 높이 46을 뺀
SidebarBottomGap으로 이관합니다. 제목 아래의 제목/헤더 기준은 그대로 유지합니다.
'기본 위치'로 선택한 위치의 보정 값을 기본값으로 되돌릴 수 있습니다.
위치 선택 및 보정 값은 %LOCALAPPDATA%\CodexUsageOverlay\settings.json에 저장합니다.
제목 아래 보정은 새 TitleOffsetX/TitleGap 설정을 사용합니다.
옛 title 설정과 0.5.1의 고정 제목 아래 좌표는 다음 일반 실행에서 재사용하지 않습니다.
이번 소스 수정·빌드만으로 실제 사용자 설정을 바꾸지는 않습니다.
위치 전환은 메인 창에서 합니다.

제목이 없거나 후보가 모호하거나 접근성 읽기 시간이 초과되면 제목 아래 오버레이를 숨기고,
메인 설정 창에 위치 확인 상태를 표시합니다. 이때는 '사이드바' 위치를 선택할 수 있습니다.
사이드바 폭이나 고정 좌표를 추측해 대신 표시하지 않으며, 위치 확인 실패를 한도 값으로 바꾸지 않습니다.
접근성 읽기는 별도 백그라운드 스레드에서 수행하고 결과를 캐시합니다.
메뉴 열기나 사용자 입력 없이 읽으며 메인 창의 응답과 X 종료를 막지 않도록 분리합니다.
현재 앱의 MainTitlebar-/ApplicationMenuPageHeader- 클래스 접두사,
ToolBar 역할과 문서 제목 일치를 기준으로 찾습니다.
Windows UI Automation은 표준 인터페이스지만 이 앱 내부 클래스 구조는 공식 확장 계약이 아닙니다.
Codex 업데이트로 구조가 바뀌면 재검증이 필요합니다.
접근성은 표시 위치 확인용이며 실제 한도는 기존 공식 App Server로 조회합니다.
배지 전체 폭·높이를 넣을 공간이 없으면 no_space 상태로 숨기며 아래쪽 요소를 잘라 표시하지 않습니다.
추가 초기화 항목의 표시 여부, 위치 보정이나 대상 창 크기를 조정하세요.

오버레이 표시 항목
설정 창은 탐색 버튼으로 '오버레이', '표시 위치·테마' 두 화면을 전환합니다.
오버레이 화면에서는 읽기 전용 미리보기와 두 체크박스를 제공합니다.
- 주간 초기화 날짜·시각
- 초기화 D-day
남은 한도와 갱신 상태·시각은 항상 유지됩니다.
체크박스를 바꾸면 미리보기에 바로 반영됩니다.
드래그, 개별 좌표/폰트/폭/겹침 순서나 배지 전체 크기 조정 도구는 제공하지 않습니다.
배지 외부 표시 위치와 테마는 기존 드롭다운에서 선택합니다.

남은 한도는 배지 왼쪽 10 DIP에서 시작하며 D-day는 같은 줄의 한도 문구 바로 오른쪽에 표시합니다.
실제 문구 폭 + 8 DIP 간격으로 배치하며 긴 한도 문구는 D-day 공간을 남기고 줄임표로 표시합니다.
D-day를 끄면 남은 한도가 사용 가능한 줄 폭을 모두 사용합니다.
초기화 날짜·시각은 세 번째 줄 전체 폭을 사용합니다.
날짜·시각을 켜면 320×82 DIP, 끄면 D-day 표시 여부와 관계없이 320×58입니다.
날짜를 끄고 D-day만 켜도 '초기화 ·' 접두사는 붙이지 않습니다. 기존 날짜/D-day 선택은 유지합니다.
미리보기는 배지 자체의 둥근 테두리만 표시하며 별도 사각 외곽선과 기본 탭 프레임은 사용하지 않습니다.
탐색 버튼과 체크박스도 선택한 테마에 맞춰 배경을 그립니다.

미리보기와 실제 배지는 같은 렌더러와 현재 메모리의 조회 상태·선택한 테마를 사용합니다.
성공값이 없으면 연결 대기/확인 불가를 표시하며 예시 잔여율로 대체하지 않습니다.
체크박스 변경 때문에 실제 계정을 새로 조회하거나 별도 worker를 추가하지 않습니다.
표시 선택은 변경 후 약 0.4초 뒤 settings.json의 BadgeLayout에 자동 저장하고 종료 전에도 저장합니다.
이전 배치 설정의 날짜/D-day 선택을 유지하고 좌표/폰트/크기/순서는 고정 기본값으로 이관합니다.
옛 상태 아이콘 설정은 무시하며 아이콘 공간도 남기지 않습니다.
이관은 다음 일반 실행에서 적용하며 개발 검사/미리보기 렌더링은 실제 사용자 설정을 쓰지 않습니다.
실제 오버레이 자체는 클릭을 아래 앱으로 통과시킵니다.

주간 초기화 날짜와 D-day
공식 응답의 Codex 주간 한도(10080분)에 있는 실제 초기화 시각을 사용합니다.
데이터 누락/잘못된 값/서로 충돌하는 주간 일정은 확인 불가로 표시합니다.
D-day는 Windows 표시 시간대의 달력 날짜 차이이며 남은 시간/24시간을 올림한 값이 아닙니다.
오늘의 미래 시각이면 D-DAY, 이미 지난 시각이면 갱신 필요를 표시합니다.
갱신 중/조회 실패/오래된 데이터에 남은 일정은 이전 일정임을 구분합니다.

조회 문제 확인
실제 한도 조회가 실패하면 오버레이 화면에 '문제 확인' 버튼이 나타납니다.
처음에는 닫힌 상태이며 누르면 원인/마지막 성공 시각/조회 시도 시각/다음 조치를 쉽게 설명합니다.
정상, 최초 연결 대기와 시간이 지나 자연스럽게 오래된 값이 된 경우에는 버튼을 표시하지 않습니다.
조회가 복구되면 안내 내용을 지우고 자동으로 닫아 숨깁니다.
펼친 안내는 현재 메모리의 실패 정보를 사용하며 새 조회/worker/파일 캐시를 만들지 않습니다.
원시 RPC, 인증 토큰, 계정 ID나 파일 경로 원문은 안내에 노출하지 않습니다.
별도의 조회 상세 화면은 제공하지 않습니다.

테마
설정 창과 배지에 Codex와 어울리는 중립적인 라이트/다크 스타일을 적용합니다.
상태별 색은 선택한 테마의 팔레트를 사용하며 한도 문구와 15% 미만 경고 조건,
공식 조회 및 클릭 통과 동작은 그대로 유지합니다.
- Codex 따라가기: 기본값. Codex에 저장된 데스크톱 테마를 읽습니다.
- Windows 따라가기: Windows 앱 모드를 따릅니다.
- 라이트 / 다크: 원하는 팔레트를 직접 선택합니다.
선택은 Overlay의 settings.json 안 ThemeMode에 저장합니다.
고대비 모드에서는 SystemColors의 대비를 우선합니다.

Codex 따라가기는 절대 경로 CODEX_HOME 아래 또는 기본
%USERPROFILE%\.codex\config.toml의 [desktop] appearanceTheme를 약 2초마다 읽습니다.
지원 값은 system/light/dark이며 system은 Windows AppsUseLightTheme를 따릅니다.
파일 없음/손상/미지원 구문·값은 설정 창에 상태를 표시하고 Windows 테마로 대체합니다.
Windows 값도 확인하지 못하면 확인 불가 상태와 기본 다크를 사용합니다.
이는 OpenAI.Codex 26.1029.7803.0에서 확인한 로컬 저장 형식에 의존하며,
공식 테마 동기화 API는 아닙니다. Codex 원본 설정은 수정하지 않습니다.
관리 설정, 실행 중인 Codex에만 전달된 다른 CODEX_HOME, 미저장 메모리 설정과
차이가 날 수 있으므로 수동 테마 선택도 제공합니다.
Windows 제목 표시줄이나 일부 기본 숫자 입력 컨트롤은 OS 스타일을 유지할 수 있습니다.

갱신과 상태
- 연결된 Codex 계정의 실제 한도입니다. 대화 글자 수로 토큰을 추정하지 않습니다.
- 공식 Codex App Server의 account/rateLimits/read를 사용합니다.
- ChatGPT 창이 활성화돼 있는 동안 60초 간격으로 조회합니다.
  다른 앱을 사용하는 동안 정기 조회를 멈춥니다.
- '지금 갱신'으로 수동 갱신할 수 있습니다. 연속 클릭은 5초 간격으로 제한됩니다.
- 정상: 주간 잔여 비율과 마지막 성공 갱신 시각이 표시됩니다. 숫자는 실제 조회값입니다.
- 조회 중: '한도 확인 중' 또는 '갱신 중 · 마지막 시각'으로 표시합니다.
- 실패: 마지막 성공값이 있으면 '이전 값' 및 '갱신 실패 · 마지막 시각'으로 표시합니다.
- 3분 이상 오래된 값: '이전 값' 및 '오래된 값 · 마지막 시각'으로 표시합니다.
- 성공값이 없으면 '한도 확인 불가'로 표시합니다. 0%나 100%로 추정하지 않습니다.
- 초기화 시각과 자세한 상태는 설정 창에서 볼 수 있으며,
  배지의 주간 초기화 날짜와 D-day도 표시 여부를 선택할 수 있습니다.
  시각은 Windows의 현재 시간대로 표시합니다.
- 5시간 한도와 주간 한도가 함께 반환되면 각각 구분합니다.

주간 한도 부족 표시
- 반올림 전 주간 잔여율이 15% 미만이면 문구 색과 부족 안내로 강조합니다. 0%는 소진으로 구분합니다.
- 상태 아이콘은 사용하지 않으며 남은 한도와 갱신 상태·시각은 유지합니다.
- 조회 실패나 오래된 값은 기존의 '이전 값' 및 마지막 성공 시각 표시를 유지합니다.
- 갱신 중·실패·3분 이상 지난 데이터에는 마지막 성공 시각과 데이터 상태를 우선 표시합니다.
- 현재 조사한 기본 앱도 빨간색 기준은 15% 미만이지만, 아이콘이 나타나는 조건은 별도입니다.

- 기본 앱의 숫자는 반올림되므로 15%로 보여도 실제 값이 15% 미만이면 빨간색일 수 있습니다.
  이는 현재 조사한 버전의 동작이며 앱 업데이트로 달라질 수 있습니다.

창 동작
ChatGPT 창이 활성 상태일 때만 표시합니다. ChatGPT를 최소화하거나 다른 앱으로 전환하면 숨깁니다.
이 프로그램의 메인 창을 최소화하는 것만으로 오버레이를 숨기거나 조회를 중지하지 않습니다.
ChatGPT 창 위치와 크기를 기준으로 다시 배치하고 현재 창의 DPI 배율을 적용합니다.
오버레이의 클릭은 아래 ChatGPT 창으로 통과하며 입력 포커스를 가져오지 않습니다.
설정 창이 활성 상태일 때도 오버레이는 숨겨집니다.

설정 다시 열기 / 종료
UsageOverlay.exe를 다시 열면 기존 메인 창을 복원합니다. 작업 표시줄에서도 복원할 수 있습니다.
'종료' 버튼과 제목 표시줄의 X는 모두 프로그램을 완전히 종료합니다.
종료 시 이 보조 프로그램이 띄운 조회 프로세스도 정리합니다.
기존 ChatGPT/Codex 프로세스는 종료하지 않습니다.

개발 및 재빌드
build.ps1은 PC의 기존 Windows C# 컴파일러로 .build에 실행 파일을 빌드합니다.
package.ps1은 dist\codex-usage-overlay에 실행 파일·보조 파일·문서를 모으고,
dist\codex-usage-overlay-windows-x64.zip을 생성합니다. 외부 패키지를 설치하지 않습니다.
현재 ZIP은 이 PC의 실제 실행 경로 설정을 포함하는 개인용 로컬 결과물이며 공개 배포하지 않습니다.

이 스크립트들은 개발·배포용이며 일반 사용자는 PowerShell을 실행할 필요가 없습니다.

좌표/실행 경로/주간 경고 검사: .build\UsageOverlay.exe --self-test .build\geometry-test.json
테스트 모양 렌더링: .build\UsageOverlay.exe --render-samples .build\warning-samples
렌더 모드는 테스트용 호스트로 라이트/다크 설정 창과 배지를 PNG로 저장합니다.
실제 계정/worker를 사용하거나 사용자 설정을 쓰지 않습니다.
정상/부족/소진/갱신 실패 배지의 수치·시각은 테스트값이며 실제 한도 조회 검증이 아닙니다.
진단 모드: 휴대용 폴더의 UsageOverlay.exe --diagnostics <저장할 JSON 파일 경로>
진단 모드는 확인 시각/표시 상태/좌표/자식 PID 등만 이 폴더에 기록합니다.
일반 실행에서는 이 파일을 갱신하지 않습니다.

공식 조회 설명
https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt

기본 표시 상태에 따른 오버레이 표시 조정
- 사용자가 제공한 화면에는 주간 한도가 초기화되어 100% 남았을 때도 기본 아이콘이 보입니다.
  이는 15% 미만의 빨간 경고색 조건과 별개인 사례입니다.
  모든 계정·버전에서 항상 보이거나 한도 정책이 바뀌었다고 단정하지 않습니다.
- 주간 잔여량을 확인할 수 있는 기본 사용량 아이콘이 보이면 보조 오버레이를 숨기고,
  사라지면 선택한 위치에 다시 표시하는 방식을 우선 검토합니다.
- 다른 위치에서 계속 보고 싶을 때는 세션 제목 아래 등으로 위치를 바꾸는 방식도 고려합니다.
  현재 수동 제목 아래/사이드바 위치 선택은 유지합니다.
- 15% 미만이라는 숫자만으로 기본 아이콘이 보인다고 가정하지 않습니다.
- 기본 아이콘 감지와 자동 숨김/이동은 아직 구현하지 않았습니다.
  감지가 불확실하면 기본 아이콘이 있다고 가정해 오버레이를 숨기지 않습니다.
- 이는 프로젝트 종료나 배포 중단 조건이 아닙니다.
- 소스 수정/빌드와 설치본 교체/프로그램 실행은 구분합니다.
  설치/업데이트/프로그램 실행은 해당 작업에 대한 사용자의 명시적 허용 후 진행합니다.

배포와 실행
현재 소스 버전은 0.7.0이며 기본 표시 위치는 실제 세션 제목 아래입니다.
다운로드 목록: https://github.com/JooWon0712/codex-usage-overlay/releases
0.7.0부터 Setup과 포터블 ZIP을 함께 빌드하며 공개된 파일은 다운로드 목록에서 확인합니다. 기존 v0.6.18 포터블 릴리스도 유지합니다.
새 릴리스 자산은 codex-usage-overlay-windows-x64.zip, codex-usage-overlay-setup-windows-x64.exe,
SHA256SUMS.txt, codex-usage-overlay.intoto.jsonl 네 개입니다. 앱 EXE는 ZIP과 Setup 안에 포함됩니다.
정식 버전 태그의 빌드/검사/출처 증명이 성공하면 게시하며 공개 여부는 다운로드 목록에서 확인하세요.

Setup 설치와 수동 업데이트
codex-usage-overlay-setup-windows-x64.exe는 관리자 권한 없이 현재 사용자에게 설치합니다.
기본 경로는 %LOCALAPPDATA%\Programs\CodexUsageOverlay이며 업데이트는 이전에 선택한 설치 폴더를 사용합니다.
시작 메뉴 바로가기를 만들며 바탕 화면 바로가기는 선택입니다. 설치 후 앱을 자동 실행하거나 로그인 자동 시작을 등록하지 않습니다.
앱의 '업데이트 확인'은 기본 브라우저로 Releases를 열기만 합니다. 자동 버전 조회/다운로드/설치는 하지 않습니다.
새 Setup은 사용자가 직접 내려받아 실행합니다. 실행 중인 앱이 있으면 먼저 닫지 않는 사전 확인을 하고,
사용자 동의 뒤 정상 종료와 소유 작업의 실제 종료를 확인한 다음 파일을 변경합니다.
무인 설치/제거에서 확인된 앱의 종료를 허용하려면 /ALLOWAPPCLOSE=1을 명시해야 하며 기본은 중단입니다.
오래된 앱이나 확인할 수 없는 실행 상태이면 X/종료로 직접 닫은 뒤 다시 시도합니다.
Windows '설치된 앱'에서 제거할 수 있습니다. 공유 사용자 설정은 업데이트/제거 모두 보존합니다.
runtime-paths.json은 설치 폴더에 없을 때만 복사하고 업데이트/제거에서 보존하므로 폴더가 남을 수 있습니다.
포터블과 설치형은 설정과 단일 실행 식별자를 공유하며 앱을 다시 실행하면 기존 창을 복원합니다.

포터블 실행
codex-usage-overlay-windows-x64.zip을 원하는 폴더에 압축 해제하고,
압축 해제한 폴더 안의 UsageOverlay.exe를 두 번 눌러 실행합니다.
Setup.exe나 install.ps1 실행, 고정 경로 설치, 관리자 권한이 필요하지 않습니다.
EXE만 따로 옮기거나 ZIP 안에서 바로 실행하지 말고 전체 폴더를 유지하세요.
일반 실행은 인수 없이 엽니다. --background 옵션은 제거했으므로,
이 옵션이 붙은 옛 바로가기는 새 버전에서 사용할 수 없습니다.
같은 파일을 다시 열면 이미 실행 중인 프로그램의 설정 창이 열립니다.
worker.mjs, probe.mjs, usage-state.mjs, runtime-paths.json을 EXE와 같은 폴더에 유지하세요.
Windows 10/11 x64, .NET Framework 4.8과 기존 Node/Codex 환경이 필요합니다.
Codex는 ChatGPT 계정으로 인증되어 있어야 합니다.
runtime-paths.json에 Node/Codex 실행 파일의 절대 경로나 EXE 폴더 기준 상대 경로를
지정할 수 있으며, 없는 실행 파일만 PATH의 node.exe/codex.exe로 대체합니다.
.cmd/.ps1 래퍼는 사용하지 않습니다. 경로나 환경을 수정하면 X 종료 후 다시 실행하세요.
Node/Codex 자체는 ZIP에 포함되지 않으며 자동으로 내려받거나 설치하지 않습니다.
다른 PC에서는 그 PC의 Node/Codex 설치, 계정 인증과 경로 설정이 필요합니다.

실행 방식
트레이 없는 일반 창 프로그램이며, 메인 설정 창이 작업 표시줄에 표시됩니다.
메인 창을 최소화해도 ChatGPT가 활성 상태이면 오버레이와 정기 조회를 계속합니다.
창 안에는 '종료' 버튼 하나를 두며, 이 버튼과 제목 표시줄의 X는
오버레이와 소유 조회 프로세스까지 정리하고 완전히 종료합니다.
설정 창은 전용 앱 아이콘과 높이 44 DIP의 여유 있는 제목 영역을 사용합니다.
최소화/X 버튼과 시스템 메뉴는 Windows 기본 동작을 유지합니다.
고대비 모드이거나 DWM을 사용할 수 없으면 표준 제목 표시줄로 대체합니다.
전용 아이콘은 실행 파일과 창에 적용하며 시스템 트레이 아이콘은 만들지 않습니다.
Overlay의 Windows 로그인 자동 시작은 사용하지 않습니다.
사용자가 이미 설정한 ChatGPT의 Windows 로그인 자동 시작은 그대로 사용합니다.
함께 시작할 구체적인 방법은 아직 선택 중입니다.
제안한 수동 전용 바로가기는 별도의 'ChatGPT + 오버레이' 실행 아이콘입니다.
그 아이콘을 누르면 ChatGPT를 열거나 활성화하면서 Overlay도 시작하는 방식입니다.
원래 ChatGPT 아이콘이나 로그인 자동 시작 경로를 바꾸는 제안은 아닙니다.
동반 실행 런처는 아직 구현하지 않았고 바로가기도 생성하지 않았습니다.
Overlay용 Run 키, Startup 폴더, 예약 작업, 프로세스 감시는 등록하지 않습니다.
일반 사용에서는 ChatGPT 창이 닫히거나 비활성화되면 오버레이 표시와 정기 한도 조회를 멈춥니다.
오버레이/표시 위치·테마 두 설정 화면 모두 설정 창이 전경이고 일반 표시 상태일 때 아래 조건으로 실제 배지를 표시합니다.
메인 창은 작업 표시줄에서 복원할 수 있습니다.

설치, 실제 실행, 바로가기 생성은 사용자가 해당 작업을 명시적으로 허용한 뒤 진행합니다.

표시 위치
표시 위치 드롭다운에서 '사이드바' 또는 '세션 제목 아래'를 선택합니다.
현재 선택한 위치의 이름을 표시하며 기존 위치 선택과 제목 아래 보정 값은 유지합니다.
사이드바는 아래의 하단 여백 방식으로 이관합니다.
Windows UI Automation으로 현재 창의 실제 제목과 헤더 영역을 읽어 위치를 정합니다.
가로 기본 위치는 제목 왼쪽에서 30 DIP 왼쪽이며 '기본 위치 보정' 값을 여기에 더합니다.
추가 보정 기본값은 0이고 세로는 제목/헤더 중 더 아래쪽 끝 + 기본 6 DIP입니다. 보정에 화면 배율을 적용합니다.
가로 배치는 읽어낸 헤더의 콘텐츠 범위 안으로 제한합니다.
폴더 아이콘을 자동 탐색하는 방식은 아니며 기존 TitleOffsetX 값이나 설정 파일을 수정/이관하지 않습니다.
기본값인 '세션 제목 아래'를 사용하거나 설정 창에서 '사이드바'를 선택하세요.
'앱에서 확인'을 누르면 메인 창을 작업 표시줄로 최소화하고 ChatGPT로 돌아갑니다.
제목 아래에서는 '기본 위치 보정'과 아래 간격을 조정할 수 있습니다.
사이드바의 가로 값은 창 왼쪽 기준이며 세로는 창 아래에서 배지 아래쪽 끝까지의 하단 여백입니다.
표시 항목에 따라 배지 높이가 자동으로 바뀌어도 하단 여백은 유지됩니다. 기존 SidebarY는 옛 배지 높이 46을 뺀
SidebarBottomGap으로 이관합니다. 제목 아래의 제목/헤더 기준은 그대로 유지합니다.
'기본 위치'로 선택한 위치의 보정 값을 기본값으로 되돌릴 수 있습니다.
위치 선택 및 보정 값은 %LOCALAPPDATA%\CodexUsageOverlay\settings.json에 저장합니다.
제목 아래 보정은 새 TitleOffsetX/TitleGap 설정을 사용합니다.
옛 title 설정과 0.5.1의 고정 제목 아래 좌표는 다음 일반 실행에서 재사용하지 않습니다.
이번 소스 수정·빌드만으로 실제 사용자 설정을 바꾸지는 않습니다.
위치 전환은 메인 창에서 합니다.

오버레이/표시 위치·테마 어느 설정 화면에서나 설정 창이 전경이고 일반 표시 상태이면
추적 중인 Codex 창 위에 실제 배지를 표시합니다.
추적 창이 없으면 보이는 Codex 창을 찾습니다. 숫자를 바꾸면 다음 화면 갱신에 배치가 반영됩니다.
이 배지는 계정의 실제 상태를 사용하며 오버레이 화면 안의 고정 예시와 다릅니다.
Codex를 활성화하거나 배지가 입력 포커스를 가져오지 않습니다.
조정용 배지는 Codex 창 바로 위에 놓이며 그보다 위에 있는 설정 창과 다른 창에 가려집니다.
Codex 자체를 항상 위로 설정했다면 그 창의 순서를 따릅니다. 설정 창이 덮으면 옆으로 옮겨 확인하세요.
다른 앱으로 이동/설정 창 최소화 때 설정 중 노출은 끝나고 일반 조건으로 돌아갑니다.
Codex 창 최소화/숨김/클로킹, 제목 아래의 유효한 앵커 없음, 공간 부족 때는 조정 중에도 숨깁니다.
정기 조회는 계속 Codex 창이 전경일 때만 수행하며 조정용 표시 때문에 추가 조회하지 않습니다.

제목이 없거나 후보가 모호하거나 접근성 읽기 시간이 초과되면 제목 아래 오버레이를 숨기고,
메인 설정 창에 위치 확인 상태를 표시합니다. 이때는 '사이드바' 위치를 선택할 수 있습니다.
사이드바 폭이나 고정 좌표를 추측해 대신 표시하지 않으며, 위치 확인 실패를 한도 값으로 바꾸지 않습니다.
접근성 읽기는 별도 백그라운드 스레드에서 수행하고 결과를 캐시합니다.
메뉴 열기나 사용자 입력 없이 읽으며 메인 창의 응답과 X 종료를 막지 않도록 분리합니다.
현재 앱의 MainTitlebar-/ApplicationMenuPageHeader- 클래스 접두사,
ToolBar 역할과 문서 제목 일치를 기준으로 찾습니다.
Windows UI Automation은 표준 인터페이스지만 이 앱 내부 클래스 구조는 공식 확장 계약이 아닙니다.
Codex 업데이트로 구조가 바뀌면 재검증이 필요합니다.
접근성은 표시 위치 확인용이며 실제 한도는 기존 공식 App Server로 조회합니다.
배지 전체 폭·높이를 넣을 공간이 없으면 no_space 상태로 숨기며 아래쪽 요소를 잘라 표시하지 않습니다.
추가 초기화 항목의 표시 여부, 위치 보정이나 대상 창 크기를 조정하세요.

오버레이 표시 항목
설정 창은 탐색 버튼으로 '오버레이', '표시 위치·테마' 두 화면을 전환합니다.
오버레이 화면에서는 예시 데이터임을 표시한 읽기 전용 미리보기와 세 체크박스를 제공합니다.
- 구독 요금제: 기본 켜짐, 갱신 시각 옆에 표시
- 주간 초기화 날짜·시각
- 초기화 D-day
남은 한도와 갱신 상태·시각은 항상 유지됩니다.
체크박스를 바꾸면 미리보기에 바로 반영됩니다.
드래그, 개별 좌표/폰트/폭/겹침 순서나 배지 전체 크기 조정 도구는 제공하지 않습니다.
배지 외부 표시 위치와 테마는 기존 드롭다운에서 선택합니다.

구독 요금제는 새 줄을 만들지 않고 '갱신 14:30 · Plus'처럼 표시합니다.
기존 공식 account/rateLimits/read 응답의 Codex 한도 버킷 planType을 함께 읽으며 추가 조회하지 않습니다.
사용자 선택에 따라 prolite는 Pro 100, pro는 Pro 200, promax는 Pro 500으로 표시합니다.
숫자는 요금제 등급의 표시명이며 원화 결제 금액이 아닙니다.
Free/Go/Plus/Team/Business/Enterprise/Edu와 나머지 요금제 표시는 유지하며 다른 검증된 특수 식별자는
판매명을 추측하지 않고 '요금제: edu_plus'처럼 표시합니다. 이 표시명 변경으로 서버 조회나 설정 파일 이관을 추가하지 않습니다.
값 없음/unknown/미지원 값은 확인 불가,
처음 연결 중이면 확인 중으로 표시합니다. 실패/갱신 중/오래된 값에서는 '이전 Plus'처럼 지난 관찰임을 구분합니다.
새 성공 응답에 요금제가 없으면 이전 요금제도 지우고 계정 변경 알림 때는 이전 한도와 요금제를 함께 지웁니다.
대상은 연결된 Codex CLI 계정이며 데스크톱 앱과 같은 계정이라고 보장하지 않습니다.
결제 금액/청구 주기/계정 이메일/인증 정보는 읽거나 표시하지 않습니다.
선택은 BadgeLayout.ShowPlan에 저장하며 기존 설정에 없으면 켜집니다.

배경 투명도는 0/10/20…100%의 10% 단위로 선택하며 기본값은 0%입니다.
0%는 불투명, 100%는 배지 바탕이 완전히 투명하며 글자와 필요한 윤곽/그림자는 남습니다.
고정 불투명 문구 바탕은 제거했고 원래의 부드러운 글자 가장자리를 유지합니다.
기존 수치는 0~100% 범위 보정 후 가장 가까운 10%로 반올림합니다(5는 올림: 82→80, 85→90).
선택한 비율을 함께 표시하고 변경을 미리보기와 실제 배지에 바로 반영합니다.
약 0.4초 뒤 자동 저장하며 종료 전에도 남은 변경을 저장합니다.
고대비 모드에서는 배경을 불투명하게 표시하되 선택한 값은 보존합니다.
표시 항목 제목과 체크 문구도 조금 키웠습니다.
라이트 글자는 0~40%에서 어두운 톤, 50~100%에서 라이트용 밝은 글자와 부드러운 어두운 그림자를 사용합니다.
40%에서 50%로 바꾸면 글자 톤이 전환됩니다.
낮은 구간은 검정 배경 위에 합성한 배지 바탕의 계산상 최저 밝기를 기준으로 글자색의 계산 대비가 4.5:1 이상이 되도록
필요한 색만 더 어둡게 합니다. 실제 화면은 샘플링하지 않으며 모든 배경의 최적 가독성을 보장하지 않습니다.
라이트의 설정 창과 배지 바탕은 뉴트럴잉크를 사용합니다. 정상 갱신 상태와 D-day는 보조 문구색으로 맞춰
정상 배지를 두 톤으로 정리하며 경고/실패 색의 의미를 유지합니다.
다크도 밝은 글자와 부드러운 아래 그림자를 사용합니다. 원래 글자의 부드러운 가장자리와 고대비의 기존 윤곽을 유지합니다.

남은 한도는 배지 왼쪽 10 DIP에서 시작하며 D-day는 같은 줄의 한도 문구 바로 오른쪽에 표시합니다.
실제 문구 폭 + 8 DIP 간격으로 배치하며 긴 한도 문구는 D-day 공간을 남기고 줄임표로 표시합니다.
D-day를 끄면 남은 한도가 사용 가능한 줄 폭을 모두 사용합니다.
초기화 날짜·시각은 세 번째 줄 전체 폭을 사용합니다.
날짜·시각을 켜면 320×82 DIP, 끄면 D-day 표시 여부와 관계없이 320×58입니다.
날짜를 끄고 D-day만 켜도 '초기화 ·' 접두사는 붙이지 않습니다. 기존 날짜/D-day 선택은 유지합니다.
미리보기는 배지 자체의 둥근 테두리만 표시하며 별도 사각 외곽선과 기본 탭 프레임은 사용하지 않습니다.
탐색 버튼과 체크박스도 선택한 테마에 맞춰 배경을 그립니다.

설정 미리보기는 프로그램 시작 때 한 번 만든 주간 96%/Plus 예시입니다.
예시 갱신 시각은 프로그램 시작 시각, 초기화 시각은 그로부터 7일(7×24시간) 뒤입니다.
D-day 예시는 같은 기준 시각의 Windows 표시 시간대로 계산하며 한국 시간에서는 D-7입니다.
생성 뒤에는 고정하므로 실시간으로 감소하거나 3분 뒤 만료되지 않습니다.
계정의 로딩/조회 실패 때문에 확인 불가/오래된 값으로 바뀌지도 않습니다.
요금제/날짜/D-day 표시 여부와 선택한 테마는 예시에 그대로 적용합니다.
예시의 Plus는 실제 계정 요금제를 확인한 결과가 아닙니다.
배경 투명도도 예시에 같이 적용합니다. 일반 테마의 미리보기 뒤에는 다크 예시 배경을 사용하고
'예시 데이터 · 다크 배경 · 프로그램 시작 시각 기준'이라고 표시합니다. 고대비 모드에서는 고대비 배경을 사용합니다.
실제 Codex 테마 감지나 화면 샘플링 결과가 아니므로 실제 Codex 위의 배지와 비쳐 보이는 색이 다를 수 있습니다.
실제 배지는 픽셀별 투명도로 배경을 처리하며
클릭 통과/창 순서/표시 조건/종료 동작은 그대로 유지합니다.
미리보기와 실제 배지는 렌더러를 공유하지만 데이터는 분리합니다.
예시 96%는 실제 조회 성공이나 잔여 한도를 뜻하지 않습니다.
Codex 창 위의 실제 배지는 공식 조회값과 로딩/실패/오래된 값 구분을 그대로 유지하며,
성공값이 없을 때 예시 잔여율로 대체하지 않습니다.
미리보기용 재조회/worker/저장을 추가하지 않습니다.
표시 선택은 변경 후 약 0.4초 뒤 settings.json의 BadgeLayout에 자동 저장하고 종료 전에도 저장합니다.
이전 배치 설정의 날짜/D-day 선택을 유지하고 좌표/폰트/크기/순서는 고정 기본값으로 이관합니다.
옛 상태 아이콘 설정은 무시하며 아이콘 공간도 남기지 않습니다.
이관은 다음 일반 실행에서 적용하며 개발 검사/미리보기 렌더링은 실제 사용자 설정을 쓰지 않습니다.
실제 오버레이 자체는 클릭을 아래 앱으로 통과시킵니다.

주간 초기화 날짜와 D-day
실제 배지는 공식 응답의 Codex 주간 한도(10080분)에 있는 초기화 시각을 사용합니다.
데이터 누락/잘못된 값/서로 충돌하는 주간 일정은 확인 불가로 표시합니다.
D-day는 Windows 표시 시간대의 달력 날짜 차이이며 남은 시간/24시간을 올림한 값이 아닙니다.
오늘의 미래 시각이면 D-DAY, 이미 지난 시각이면 갱신 필요를 표시합니다.
갱신 중/조회 실패/오래된 데이터에 남은 일정은 이전 일정임을 구분합니다.
설정 미리보기의 고정 예시 일정은 실제 계정 일정과 별개입니다.

조회 문제 확인
실제 한도 조회가 실패하면 오버레이 화면에 '문제 확인' 버튼이 나타납니다.
미리보기의 예시 상태는 이 판단에 사용하지 않습니다.
처음에는 닫힌 상태이며 누르면 원인/마지막 성공 시각/조회 시도 시각/다음 조치를 쉽게 설명합니다.
정상, 최초 연결 대기와 시간이 지나 자연스럽게 오래된 값이 된 경우에는 버튼을 표시하지 않습니다.
조회가 복구되면 안내 내용을 지우고 자동으로 닫아 숨깁니다.
펼친 안내는 현재 메모리의 실패 정보를 사용하며 새 조회/worker/파일 캐시를 만들지 않습니다.
원시 RPC, 인증 토큰, 계정 ID나 파일 경로 원문은 안내에 노출하지 않습니다.
별도의 조회 상세 화면은 제공하지 않습니다.

테마
설정 창과 배지에 Codex와 어울리는 중립적인 라이트/다크 스타일을 적용합니다.
상태별 색은 선택한 테마의 팔레트를 사용하며 한도 문구와 15% 미만 경고 조건,
공식 조회 및 클릭 통과 동작은 그대로 유지합니다.
라이트는 사용자가 선택한 뉴트럴잉크이며 입력란/버튼/배지/지원되는 제목 표시줄에 함께 적용합니다.
배경 #CFD3D8, 표면 #DBDEE2, 본문 #20262E, 보조 문구 #444F5D를 사용합니다.
다크는 10개 시안 중 선택한 뉴트럴차콜로 배경 #171B22, 표면 #242A34, 본문 #E7EBF0, 보조 문구 #B5BEC9를 사용합니다.
정상 다크 배지도 갱신 상태와 D-day를 보조 문구색으로 통일합니다.
기존 라이트/다크 항목에 적용하므로 새 항목이나 설정 이관은 없고 고대비/자동 테마와 경고 색의 의미는 유지합니다.
닫힌 선택 상자·숫자 입력의 둥근 외곽 테두리/안쪽 여백/화살표 영역과 포커스/마우스 오버를
테마에 맞춥니다. 다크/라이트/고대비와 기존 목록·키보드·정수 직접 입력·최솟값/최댓값·증감 동작을 유지합니다.
- Codex 따라가기: 기본값. Codex에 저장된 데스크톱 테마를 읽습니다.
- Windows 따라가기: Windows 앱 모드를 따릅니다.
- 라이트 / 다크: 뉴트럴잉크 라이트 또는 뉴트럴차콜 다크를 직접 선택합니다.
선택은 Overlay의 settings.json 안 ThemeMode에 저장합니다.
고대비 모드에서는 SystemColors의 대비를 우선합니다.

Codex 따라가기는 절대 경로 CODEX_HOME 아래 또는 기본
%USERPROFILE%\.codex\config.toml의 [desktop] appearanceTheme를 약 2초마다 읽습니다.
지원 값은 system/light/dark이며 system은 Windows AppsUseLightTheme를 따릅니다.
파일 없음/손상/미지원 구문·값은 설정 창에 상태를 표시하고 Windows 테마로 대체합니다.
Windows 값도 확인하지 못하면 확인 불가 상태와 기본 다크를 사용합니다.
이는 OpenAI.Codex 26.1029.7803.0에서 확인한 로컬 저장 형식에 의존하며,
공식 테마 동기화 API는 아닙니다. Codex 원본 설정은 수정하지 않습니다.
관리 설정, 실행 중인 Codex에만 전달된 다른 CODEX_HOME, 미저장 메모리 설정과
차이가 날 수 있으므로 수동 테마 선택도 제공합니다.
Windows 제목 표시줄과 운영체제가 그리는 일부 내부 요소는 OS 스타일을 유지할 수 있습니다.

갱신과 상태
아래 내용은 Codex 창 위에 떠 있는 실제 배지에 적용하며 설정 미리보기는 고정 예시를 사용합니다.
- 연결된 Codex 계정의 실제 한도입니다. 대화 글자 수로 토큰을 추정하지 않습니다.
- 공식 Codex App Server의 account/rateLimits/read를 사용합니다.
- Codex 창이 전경인 동안 60초 간격으로 조회합니다.
  다른 앱을 사용하는 동안 정기 조회를 멈추며 설정 창의 조정용 노출 때문에 추가 조회하지 않습니다.
- '지금 갱신'으로 수동 갱신할 수 있습니다. 연속 클릭은 5초 간격으로 제한됩니다.
- 정상: 주간 잔여 비율과 마지막 성공 갱신 시각이 표시됩니다. 숫자는 실제 조회값입니다.
- 조회 중: '한도 확인 중' 또는 '갱신 중 · 마지막 시각'으로 표시합니다.
- 실패: 마지막 성공값이 있으면 '이전 값' 및 '갱신 실패 · 마지막 시각'으로 표시합니다.
- 3분 이상 오래된 값: '이전 값' 및 '오래된 값 · 마지막 시각'으로 표시합니다.
- 성공값이 없으면 '한도 확인 불가'로 표시합니다. 0%나 100%로 추정하지 않습니다.
- 초기화 시각과 자세한 상태는 설정 창에서 볼 수 있으며,
  배지의 주간 초기화 날짜와 D-day도 표시 여부를 선택할 수 있습니다.
  시각은 Windows의 현재 시간대로 표시합니다.
- 5시간 한도와 주간 한도가 함께 반환되면 각각 구분합니다.

주간 한도 부족 표시
- 반올림 전 주간 잔여율이 15% 미만이면 문구 색과 부족 안내로 강조합니다. 0%는 소진으로 구분합니다.
- 상태 아이콘은 사용하지 않으며 남은 한도와 갱신 상태·시각은 유지합니다.
- 조회 실패나 오래된 값은 기존의 '이전 값' 및 마지막 성공 시각 표시를 유지합니다.
- 갱신 중·실패·3분 이상 지난 데이터에는 마지막 성공 시각과 데이터 상태를 우선 표시합니다.
- 현재 조사한 기본 앱도 빨간색 기준은 15% 미만이지만, 아이콘이 나타나는 조건은 별도입니다.
  기본 아이콘이 정확히 15%부터 나타난다고 확인한 것은 아닙니다.
- 기본 앱의 숫자는 반올림되므로 15%로 보여도 실제 값이 15% 미만이면 빨간색일 수 있습니다.
  이는 현재 조사한 버전의 동작이며 앱 업데이트로 달라질 수 있습니다.

창 동작
일반 사용에서는 ChatGPT 창이 활성 상태일 때 표시합니다. 두 설정 화면 모두 설정 창이 전경이고 일반 표시 상태일 때 실제 배지를 표시합니다.
ChatGPT 최소화/숨김, 설정 창 이외의 다른 앱으로 전환하면 숨깁니다.
이 프로그램의 메인 창을 최소화하는 것만으로 오버레이를 숨기거나 조회를 중지하지 않습니다.
ChatGPT 창 위치와 크기를 기준으로 다시 배치하고 현재 창의 DPI 배율을 적용합니다.
오버레이의 클릭은 아래 ChatGPT 창으로 통과하며 입력 포커스를 가져오지 않습니다.
설정 창의 두 화면은 같은 대상 창/앵커/공간 조건을 사용합니다.

설정 다시 열기 / 종료
UsageOverlay.exe를 다시 열면 기존 메인 창을 복원합니다. 작업 표시줄에서도 복원할 수 있습니다.
'종료' 버튼과 제목 표시줄의 X는 모두 프로그램을 완전히 종료합니다.
종료 시 이 보조 프로그램이 띄운 조회 프로세스도 정리합니다.
기존 ChatGPT/Codex 프로세스는 종료하지 않습니다.

휴대용 폴더 이동과 업데이트
- 폴더를 이동하거나 업데이트하기 전에 메인 창의 X를 눌러 완전히 종료하세요.
- 이동할 때는 EXE와 보조 파일을 포함한 전체 폴더를 함께 옮깁니다.
- 업데이트할 때는 새 ZIP의 전체 폴더로 교체한 뒤 UsageOverlay.exe를 실행합니다.
  실행 중인 파일 위에 덮어쓰거나 EXE만 교체하지 않습니다.
  패키징 중 기존 결과물 파일이 잠겨 있으면 교체를 중단하며 앱을 강제 종료하지 않습니다.
- 고정 설치 경로를 검사하거나 기존 설치본으로 자동 연결하지 않습니다.
- 위치 설정은 %LOCALAPPDATA%\CodexUsageOverlay\settings.json을 계속 사용합니다.
  이전 버전과 설정을 공유하므로 폴더를 옮겨도 설정이 유지됩니다.
  단, 옛 title 설정과 0.5.1 고정 제목 아래 좌표는 새 제목 기준 보정에 재사용하지 않습니다.
- 여러 사본도 같은 단일 실행 식별자를 사용합니다.

개발 및 재빌드
build.ps1은 PC의 기존 Windows C# 컴파일러로 .build에 실행 파일을 빌드합니다.
package.ps1은 dist\codex-usage-overlay에 실행 파일·보조 파일·문서를 모으고,
dist\codex-usage-overlay-windows-x64.zip을 생성합니다. 외부 패키지를 설치하지 않습니다.
옵션 없는 로컬 빌드는 이 PC에서 찾은 Node/Codex 실행 경로를 기록합니다.
build.ps1 또는 package.ps1의 -PortableRuntimePaths 옵션은 node.exe/codex.exe만 기록하며 컴파일할 때 Codex 설치/인증이 필요하지 않습니다.
GitHub CI는 이 배포용 옵션을 사용합니다. 프로그램을 실제로 사용할 때는 해당 PC의 Node/Codex 설치와 인증이 필요합니다.
생성물과 로컬 경로 설정은 Git에서 제외합니다.
이 스크립트들은 개발·배포용이며 일반 사용자는 PowerShell을 실행할 필요가 없습니다.
설치형 개발은 Inno Setup 6.7.4를 사용합니다. tools\prepare-inno.ps1을 명시적으로 실행하면
고정 SHA-256/제작자 서명을 확인한 컴파일러를 작업 폴더의 포터블 모드로 준비하며 Windows 설치 등록은 하지 않습니다.
기존 컴파일러가 있으면 직접 -CompilerPath로 지정할 수 있습니다.
Setup 빌드 예시:
$compiler = .\tools\prepare-inno.ps1
.\setup.ps1 -PayloadPath .\dist\codex-usage-overlay -CompilerPath $compiler -OutputDirectory .\dist
.\setup.test.ps1 -SetupPath .\dist\codex-usage-overlay-setup-windows-x64.exe
setup.ps1은 이미 검증된 7파일 포터블 payload를 소비하며 앱을 다시 빌드하거나 설치하지 않습니다.
일반 setup.test.ps1은 설치를 실행하지 않습니다. -Integration 및 tools\test-setup-lifecycle.ps1은
일회용 GitHub 호스팅 Windows 실행기에서만 허용하며 사용자 PC의 설치/실제 계정/일반 UI 검증과 구분합니다.
Node 검사: node --test probe.test.mjs worker.test.mjs tools/release.test.mjs
좌표/실행 경로/주간 경고 검사: .build\UsageOverlay.exe --self-test .build\geometry-test.json
테스트 모양 렌더링: .build\UsageOverlay.exe --render-samples .build\warning-samples
렌더 모드는 테스트용 호스트로 라이트/다크 설정 창과 배지를 PNG로 저장합니다.
실제 계정/worker를 사용하거나 사용자 설정을 쓰지 않습니다.
정상/부족/소진/갱신 실패 배지의 수치·시각은 테스트값이며 실제 한도 조회 검증이 아닙니다.
진단 모드: 휴대용 폴더의 UsageOverlay.exe --diagnostics <저장할 JSON 파일 경로>
진단 모드는 확인 시각/표시 상태/좌표/자식 PID 등만 이 폴더에 기록합니다.
일반 실행에서는 이 파일을 갱신하지 않습니다.

GitHub 빌드 출처 증명과 자동 게시
워크플로: https://github.com/JooWon0712/codex-usage-overlay/actions/workflows/windows-build.yml
PR은 빌드만, main push/main 수동 실행은 빌드와 출처 증명을 수행합니다. Actions 아티팩트 보관 기간은 30일입니다.
정식 vMAJOR.MINOR.PATCH 태그 push만 Release를 게시하며 AssemblyVersion/AssemblyFileVersion X.Y.Z.0과 일치하고
태그 커밋이 origin/main에 포함돼 있어야 합니다. 기존 태그를 재사용하거나 이동하지 않습니다.
빌드 출처 증명은 앱 EXE/포터블 ZIP/Setup EXE 세 대상을 검증합니다.
별도 게시 작업은 새 draft에 ZIP/Setup/체크섬/증명 번들 네 자산을 올려 SHA-256/크기/태그 커밋을 확인한 뒤 공개합니다.
같은 태그의 Release나 draft가 이미 있으면 중단하며 덮어쓰지 않습니다. 실패 시 미공개 draft가 남을 수 있어 재시도 전 확인해야 합니다.
이 출처 증명은 GitHub 소스/워크플로 확인용이며 Windows Authenticode나 SmartScreen의 신뢰된 게시자 서명이 아닙니다.
Release 노트의 Source commit과 함께 받은 codex-usage-overlay.intoto.jsonl을 사용한 검증 명령은 저장소 README에 있습니다.
자동 게시가 로컬 설치/앱 자동 업데이트/자동 시작을 수행하지는 않습니다. 포터블은 X 종료 뒤 전체 폴더를 교체하고 설치형은 새 Setup을 직접 실행합니다.
